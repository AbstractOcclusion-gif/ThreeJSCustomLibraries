# Impact Club Destruction Author 0.2.0

Custom Blender addon for authoring pre-fractured static props and exporting an
assembled GLB plus a versioned destruction definition. Tested with Blender 5.0.0.

## Structure parts

The profile-driven farmhouse workflow, shared material file, atlas, version-2
metadata, catalogue, commands and current limitations are documented in
[Three Kit Blender tools guide](../README.md). The new installable
package is generated by `node tools/blender/package_structure_addon.mjs`.
Legacy prop authoring and version-1 exports retain the workflow below.

## Install

In Blender, open **Edit → Preferences → Get Extensions**, open its top-right
menu and choose **Install from Disk**. Select
`impact-club-destructibles-0.2.0.zip` and enable the extension. In the 3D Viewport,
press **N** and select the **Impact Club** sidebar tab.

The ZIP includes the Cell Fracture backend; no additional fracture addon,
Python package or network access is required to use it. It uses Blender's built-in
glTF exporter. No paid art is included in the addon package.

## Author a crate from Synty or your own mesh

1. Import the source model with its UVs and materials. Establish the intended
   scale first. Blender's normal glTF material restrictions still apply; use
   Principled BSDF/image textures for export. Unity shader graphs are not converted.
2. In Object Mode, select the source meshes and click **Create Asset from Selection**.
   A new asset root and evaluated mesh copies are created. Original objects remain
   in the scene, hidden in the viewport, with their geometry/transforms unchanged.
   Source objects can be unhidden in the Outliner. Existing material datablocks
   remain shared; duplicate a material before making source-independent edits.
3. Set a unique lowercase **Asset ID**. Choose Material, then **Apply Material
   Defaults** if desired. These are editable gameplay starting values, not measured
   engineering properties. Material does not decide anchoring or breakup type.
4. Choose a piece workflow:
   - **Separate Mesh Islands** copies the intact geometry and separates disconnected
     components. Existing topology determines the result; it does not infer boards.
   - **One Piece per Source Object** retains the selected source-object boundaries.
   - **Build Voronoi Pieces** uses Cells, Seed and Interior colour. Intended for
     closed volumes such as stone or pots. Open foliage/boards are rejected. Thin or
     very small features are limited by the upstream Cell Fracture cleanup tolerance.
   - **Copy Selected Meshes as Pieces** appends copies of independently authored,
     external meshes to the Asset selected in this panel. Keep them assembled in
     the same world position as the intact asset. Their originals are preserved.
   Rebuilding islands/Voronoi **replaces the existing generated pieces**; use Blender
   Undo to recover prior edits. Source objects and intact copies are retained.
5. Inspect/edit the pieces in Blender. Return Explode Preview to zero before editing
   transforms, separating faces or joining pieces. After manual duplication or
   separation, use **Refresh Piece IDs**. It repairs duplicate/missing IDs while
   preserving valid existing identifiers. Newly separated pieces must remain
   children of the asset root and retain the Piece role copied by Blender.
6. Select individual pieces and choose **Dynamic**, **Anchored** or **Cosmetic**.
   A stump can be Anchored while trunk sections are Dynamic and leaves Cosmetic.
   Assign section labels for larger objects and choose **By Section**. Use
   **Apply Active Piece Settings to Selected** for a batch of selected pieces.
7. Choose **Box** or **Convex Hull**, then **Generate Collision Proxies**. Regenerate
   after geometry changes. Show collision proxies to inspect them. A failed,
   non-convex or over-64-vertex hull is replaced by an enclosing box with an explicit
   warning; export validation retains that warning. No invalid hull is silently
   accepted. Box proxies can overfill hollow objects: split those into appropriate
   parts instead of expecting a box to preserve openings. Editable proxies must
   remain closed and convex. Apply proxy modifiers before exporting.
8. Switch **Intact / Pieces** and adjust **Explode Preview** to inspect the assembly.
   This is an inspection view, not a simulated destruction or baked explosion.
9. **Validate Asset**, then **Export Destructible**. Choose an existing folder and
   filename. A pair is written: `name.glb` and `name.destructible.json`. Replacing
   existing exports requires the explicit **Replace Existing Files** option.

Validation details are also saved in a Blender Text datablock named
`ICD Validation - <asset_id>`. Dynamic piece count is checked against the configured
asset budget. Cosmetic pieces have no collider or mass, but still cost rendering.

## What the export means

Both intact meshes and broken meshes exist in the GLB at their **assembled**
positions, regardless of the current visibility/explode preview. A consumer must
show the intact nodes initially and reveal selected broken nodes on destruction;
loading every GLB node visibly will deliberately show both states overlapping.
The addon does not modify or add a destruction manager to the current game.

The JSON is the asset definition. Geometry and collision data use **metres, +Y up,
right-handed**, matching Blender's GLB export and Three.js. Scene unit scale is
captured at asset creation. Placement translation/rotation of the asset root is
excluded; root parenting or non-unit scale is rejected. Resize source geometry
before creating an asset or edit its mesh, rather than scaling the asset root.
Piece transforms are baked into local geometry, so manifest positions suffice;
mesh/collider vertices and GLB node positions share the same coordinate system.

Proxies are exported as convex vertex/face arrays usable by Cannon's
`ConvexPolyhedron`. Even a box uses that representation. `authorShape` records
BOX, HULL, BOX_FALLBACK or CUSTOM. Intact collision is a compound list with an
individual position per shape. Fragment collision is relative to its render-node
pivot. UVs/materials are retained by Blender's exporter; collision meshes themselves
are omitted from the GLB.

Total authored mass is distributed across Dynamic and Anchored pieces using proxy
volume times Mass Multiplier. Their authored masses sum to Total Mass. An Anchored
piece's `massKg` is its authored mass allocation; the game must use a static body
while anchored. Cosmetic pieces have `massKg: 0` and `collider: null`.

Material, intact support and breakup mode are independent. Sections are labels;
there is no implicit joint graph, support inference, connection strength,
progressive structural collapse or runtime re-fracturing. Thresholds and effects
names are metadata awaiting game integration. Effects, sounds and destruction
scoring are not baked into the mesh and are not previewed by this addon.

## Verification and limits

The repository includes an executable Blender authoring check and a separate
Three.js/Cannon export verifier in `tools/blender/tests/`. They exercise the actual
Synty crate, Voronoi geometry, roles/sections, preview-safe exports, unit conversion,
source preservation, ID repair, validation and file replacement protection.

The Node verifier loads the resulting GLBs with the installed GLTFLoader, compares
render/proxy transforms, checks winding/convexity/enclosure and makes ground
contacts with real Cannon bodies. It stubs image decoding: it is not proof of
rendered texture appearance. These checks do not establish mobile performance,
final material quality, UI ergonomics or a working in-game destruction manager.
